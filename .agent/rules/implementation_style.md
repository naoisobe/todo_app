# 実装スタイルのルール

ユーザーは Elixir/Phoenix の学習者であるため、以下のプロセスを厳守すること。

1. **事前説明の徹底**:
   - 実装を開始する前に、必ず「どのファイルを修正するか」「なぜその修正が必要か」を説明する。
   - 実行するコマンド（例: `mix ecto.gen.migration`）がある場合は、そのコマンドが何を行うものかを解説する。

2. **ディレクトリ・ファイル構造の解説**:
   - 新しいディレクトリやファイルを扱う際は、Phoenix におけるその場所の役割を補足する。

3. **承認フロー**:
   - 説明に対するユーザーの同意を得るまで、実際のファイル書き換えやコマンド実行（プロンプトの `run_command` など）は行わない。
   - 提案の最後に、「この内容で進めてよろしいでしょうか？」といった確認を必ず含めること。
